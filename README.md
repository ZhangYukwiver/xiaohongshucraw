# 小红书直播间用户数据采集（本地版）

守着一场小红书直播，记下弹幕，再逐个打开发言用户的主页，记下上面公开的资料，导出成表格。

用本机 Chrome 开一个独立登录态的窗口，让小红书网页自己加载数据，采集器只读页面已经拿到的内容。不接外部 AI，不上传，登录态和采集结果都只在 `.local-data/`。

## 快速开始

需要 Node 22.18+ 或 24.2+，以及 Chrome（没有 Chrome 会找 Edge；其他 Chromium 内核浏览器用环境变量 `XHS_CHROME_PATH` 指定路径）。

```bash
npm install
```

```bash
npm run live -- "<直播间链接>"
```

第一次运行会弹出一个独立的 Chrome 窗口，用小红书 App 扫码登录，登录后自动进直播间。之后一边记弹幕，一边在另一个标签页里逐个打开发言用户的主页。直播结束、主页都查完后自动退出；也可以随时按 Ctrl+C，已记下的会先保存。

链接从浏览器地址栏（`https://www.xiaohongshu.com/livestream/…`）或 App 的分享里复制都行，整段分享文案原样贴进来也认，也可以只给房间号。链接里有 `&`，记得加引号。

## 采集什么

结果在 `.local-data/live.csv`，一行一条弹幕，Excel、Numbers、WPS 直接打开：

| 列 | 来源 |
| --- | --- |
| 时间、直播间、主播、名字、弹幕内容 | 直播间收到的弹幕 |
| 小红书号、IP属地 | 发言用户的主页 |
| 作品数、作品（首屏标题） | 主页「笔记」：总数和第一批，30 条左右 |
| 收藏数、收藏（首屏标题） | 主页「收藏」：总数和第一批 10 条；对方没公开收藏的写「未公开」 |
| 主页 | 用户主页链接 |

`live.json` 是原始数据，另外还有头像、简介、关注数、粉丝数、获赞与收藏，以及作品和收藏里每篇笔记的 ID、`xsec_token`。

## 采集原理与边界

- **「IP」是 IP 属地**：网页上只看得到主页显示的 IP 属地（省份，海外是国家），拿不到真实 IP 地址。有的用户主页不显示 IP 属地，这一列就空着。
- **用你的账号进直播间**：直播间里会像平时一样显示「你的昵称 来了」。访客身份不行：2026-09-27 实测，工具开的访客窗口一进直播间就被转到风控页。
- **只记进直播间之后的弹幕**：之前的历史弹幕网页不给。弹幕取自直播间网页自己收到的 WebSocket 消息，只要文字弹幕，进场、点赞、礼物都不记。
- **页面驱动**：主页资料读的是页面状态（Pinia）里网页自己加载好的内容。不伪造 `x-s` 等签名，不直接调接口。
- **查主页排队慢慢来**：每开一个主页间隔 5–10 秒，收藏公开的人要多开一页，平均十几秒查一个人。人多的直播间查不过来很正常：实测 6700 人在线的直播间，110 秒来了 550 条弹幕、347 人发言，只查完 7 人。没查完的不会丢，之后运行 `npm run live`（不带链接）会接着查。
- **验证码和风控**：查主页时弹验证码会停下等你在窗口里手动完成，工具不替你过验证；碰到风控页（例如「安全限制 300012」）或登录失效就停止查主页，弹幕照常记。直播间本身也被风控时直接停下，已记下的都保存。
- **没有无界面运行**：2026-09-26 实测，无头 Chrome 以访客身份打开首页就被判「IP存在风险 300012」，同一网络下有界面的 Chrome 正常。为了不连累账号，只用有界面窗口。
- **只读**：不发弹幕、不点赞、不关注、不私信。
- 小红书网页改版可能让它读不到数据：进不了直播间、读不到登录状态时会明确报错。

## 数据放在哪

`.local-data/`，已被 git 忽略：

- `browser-profile/`：独立浏览器配置，里面有小红书登录 Cookie，不要拷给别人
- `live.json`、`live.csv`：直播间弹幕和发言用户的资料，是别人的个人信息，别外传

## 还没做的，以及能直接用的开源项目

能用同样「页面驱动、只读」方式做的，留到后面；做不了或不值得自己写的，列了可以直接用的开源项目。开源项目信息核对于 2026-09-26（源码和 LICENSE），用之前请再看一眼它们的最新说明。

| 功能 | 现状 | 建议 |
| --- | --- | --- |
| 直播间的礼物、点赞、进场 | 后续 | WebSocket 消息里都有（`gift_comment`、`praise`、`audience_join_v2`），在 `parseFrame` 里多认几种 type 就行 |
| 发言用户的全部作品和收藏 | 后续 | 要在主页里往下翻，查得越多越容易被风控，所以默认只读第一批 |
| 无界面运行 | 做不了 | 无头 Chrome 实测会被判风控（见上），为了账号安全不做 |
| 搜索、评论 | 不做 | [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)（Apache-2.0，浏览器驱动，提供 MCP 和 REST）。它的说明提到同一账号网页端只能保留一个登录，会互相踢下线，建议用另一个账号。[NanmiCoder/MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 功能最全，但许可证是非商用学习许可，开源版输出会把用户 ID、昵称脱敏 |
| 直接调接口需要的签名 | 不需要 | 本工具不调接口。真要用：Python 用 [Cloxl/xhshow](https://github.com/Cloxl/xhshow)（MIT），Node 可参考 [lucasygu/redbook](https://github.com/lucasygu/redbook)（MIT）里的移植。签名算法随网页更新，随时可能失效 |

另外：xiaohongshu-mcp 的说明提到小红书网页端同一账号只保留一个登录。如果属实，在本工具的独立浏览器登录后，你日常浏览器里的小红书网页可能会被登出，重新登录即可。

## 开发

```bash
npm test
```

用 Node 自带的 `node --test`，覆盖弹幕解析、链接识别、表格导出和笔记卡片归一化。

- `collector/live.mjs`：入口。进直播间听 WebSocket、查发言用户主页、导出表格
- `collector/collect.mjs`：浏览器这一侧：启动独立 Chrome、等登录、等验证、读页面状态
- `collector/records.mjs`：笔记卡片归一化、计数和时间转换，纯函数
